# iTunes Classic

Неофициальный локальный медиаплеер для macOS с интерфейсом в духе iTunes 9 и Mac OS X Snow Leopard. Нативное приложение на Swift и AppKit: металлические панели, элементы Aqua, сетка альбомов и Cover Flow.

Проект не связан с Apple. iTunes и графические обозначения Apple принадлежат соответствующим правообладателям. Это ранняя экспериментальная сборка.

## Установка

Текущая экспериментальная сборка: **0.39 (39)**, **Apple Silicon (arm64)**.

1. Скачайте [iTunes-0.39-arm64.dmg](https://github.com/poltoraska/itunes-classic/releases/download/v0.39/iTunes-0.39-arm64.dmg) из [Releases](https://github.com/poltoraska/itunes-classic/releases).
2. Откройте DMG и перетащите `iTunes.app` в `Applications` («Программы»).
3. Извлеките образ и запустите приложение из «Программ».
4. Добавьте свои файлы через ⌘O или перетащите папку музыки в окно.

Приложение подписано локальным сертификатом, без Apple Developer ID и нотариального заверения Apple. При блокировке запуска используйте системный раздел «Настройки системы → Конфиденциальность и безопасность», только если доверяете скачанной сборке. [Инструкция Apple](https://support.apple.com/102445). Отключать Gatekeeper целиком не требуется.

Основной плеер требует macOS 13 или новее. Синхронизация Android и запись тегов управляемых копий в поставляемой сборке требуют **macOS 27 или новее**: так собраны используемые библиотеки PixelTransfer. Intel-сборки пока нет.

## Возможности

- Локальная аудиотека: список, сетка альбомов, раскрывающийся список композиций и Cover Flow.
- Сортировка, поиск, плейлисты, выделение нескольких треков и очередь «Далее».
- Обычный и синхронный текст: импорт LRC, подсветка строк и плавная прокрутка.
- Поиск текста через LRCLIB по явной команде пользователя.
- Редактор метаданных, обложки, мини-плеер и плавный переход между песнями.
- Видеоклипы с плавающей панелью управления и полноэкранным режимом.
- Односторонняя синхронизация музыки с Android по USB.

## Управление

| Команда | Клавиши |
| --- | --- |
| Добавить файлы или папку | ⌘O |
| Воспроизведение / пауза | Пробел |
| Поиск | ⌘F |
| Текущая композиция / возврат к клипу | ⌘L |
| Показать / скрыть текст | ⌘Y |
| Альбомы в Cover Flow | ← / → или трекпад |
| Предыдущая / следующая композиция | ⌥← / ⌥→ |
| Закрыть раскрытый альбом | Escape |

После закрытия просмотра клипа его воспроизведение продолжается. Кнопка «Вернуться к клипу», обложка «Сейчас играет» или ⌘L открывают его на текущей позиции.

## Android

Откройте **«Файл → Синхронизировать с Android…»**. Подключите один телефон, разблокируйте его и выберите USB-режим «Передача файлов». Закройте PixelTransfer/OpenMTP, чтобы освободить подключение.

Программа проверяет `Music` первого доступного для записи хранилища и копирует аудио из медиатеки Mac. Видео исключаются. Названия, исполнители, известные номера дисков/дорожек и длительность сопоставляются независимо от расширения: полный MP3-альбом не дублируется AIFF-версией. Для недостающих AIFF и других неподходящих форматов готовятся AAC/M4A-копии. Исходники на Mac не меняются.

При изменении альбома сначала передаётся и проверяется новая версия; затем удаляются сопоставленные старые аудиофайлы. Нужен свободный объём для полной новой копии. Обложки, плейлисты и посторонние файлы не удаляются. При занятом имени папки используется суффикс `(iTunes N)`; пустые старые папки могут остаться. Удаление альбома из медиатеки Mac не удаляет его на телефоне.

Первая проверка читает теги через временные копии файлов на Mac и может занять значительное время. Затем используется кэш по устройству, объекту, имени, размеру и дате. Файлы без определимых тегов останавливают проверку до записи. Изменения исходников после первого сопоставления отслеживаются через SHA-256. Изменение телефонного файла с сохранением всех признаков кэша не определяется.

Обрывы после публикации могут оставить обе версии альбома. Повторная синхронизация сопоставит их заново. После отключения кабеля могут остаться временные `.iTunes-incoming-*`, занимающие место; готовой музыкой они не считаются. Продолжения с середины файла нет. Передача на физическом телефоне в этой версии ещё требует проверки; автоматические проверки используют модель MTP и реальную конвертацию AIFF → AAC.

## Данные и сеть

Медиатека хранится локально. Аудио и содержимое телефона в интернет не отправляются. По команде поиска текста LRCLIB получает название, исполнителя, альбом и длительность одной песни; найденный текст сохраняется в локальном кэше. Автоматического сетевого поиска при смене песни нет.

## Сборка из исходников

Нужен Xcode с поддержкой установленного SDK macOS. На Apple Silicon:

```sh
./build.sh
```

Результат: `build/iTunes.app`. Или откройте `iTunes.xcodeproj`, выберите схему `iTunes` и запустите ⌘R.

Скрипт создаёт локальную идентичность подписи в `.signing/`, если её нет. Каталог исключён из Git; чужие ключи для сборки не требуются. Поставляемые MTP-библиотеки — arm64, macOS 27+; для иных систем их нужно пересобрать из исходников.

Проверки на временной медиатеке:

```sh
build/iTunes.app/Contents/MacOS/iTunes --self-test --fixtures Tests/Fixtures
```

Создание DMG после сборки:

```sh
./scripts/create-dmg.sh
```

## Компоненты и графика

MTP-мост адаптирован из PixelTransfer. Динамические libmtp и libusb поставляются с текстами LGPL-лицензий в `Resources/Libraries.bundle`; они заменяемы. Ссылки на исходники и сведения об остальных ресурсах — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Графические ресурсы и товарные знаки не объявляются собственностью проекта. Общая лицензия для авторского кода пока не выбрана.


## Изменения в исходниках 0.37

Внизу контекстных меню трека и альбома появились команды удаления. Диалог предлагает убрать только записи из медиатеки или также переместить исходники в Корзину. Удалённые записи очищаются из плейлистов и очереди; удаление текущей композиции останавливает её. Ошибки перемещения отдельных файлов сохраняют их записи. Альбом можно показать в Finder из ПКМ по обложке или меню «…» раскрытого альбома.

«Файл → Проверить файлы медиатеки…» в фоне проверяет существующие ссылки и предлагает убрать отсутствующие после подтверждения и повторной проверки. Отключённые тома /Volumes и ошибки доступа не считаются удалёнными файлами. Новые файлы эта команда не импортирует: используйте ⌘O. «Добавить медиатеку…» использует тот же рекурсивный импорт, ограничивая выбор одной папкой; оригиналы не копируются и слежение за папкой не включается.


## Изменения в исходниках 0.38

Новые импорты (включая перетаскивание папок) копируются в `~/Music/iTunes Classic Media/Музыка/Исполнитель альбома/Альбом/`; видеоклипы находятся в отдельном разделе. Скачанные оригиналы сохраняются. Старые записи с внешними путями не переносятся автоматически. Точное время добавления сохраняется, а «Недавно добавленные» показывает новые импорты первыми во всех режимах, независимо от алфавитной сортировки.

Правки метаданных управляемых копий записываются в MP3, AIFF, FLAC, M4A и другие форматы, поддерживаемые TagLib. Аудио не перекодируется. Имена файлов и папок обновляются по исправленным тегам; коллизии не перезаписывают чужие файлы. Подготовка копий выполняется в фоне, перед фиксацией проверяется актуальность медиатеки. При ошибке записи базы опубликованные изменения файлов откатываются. Теги внешних старых файлов пока остаются только в базе. Поддержка записи тегов в этой поставке TagLib требует macOS 27+.

Окна проверки медиатеки используют общий заголовок Snow Leopard и пульсирующую кнопку Aqua. Из сторонних компонентов добавлен TagLib 2.3.2 (заменяемая динамическая библиотека), с LGPL/MPL-лицензиями в Libraries.bundle. `scripts/build-tags.sh` пересобирает нативный модуль, используя поставляемые заголовки и библиотеку.


## Выпуск 0.39

Новая сборка объединяет изменения 0.37–0.38: удаление треков и альбомов с выбором сохранения файлов или Корзины, Finder для альбомов, проверку отсутствующих файлов, окна проверки Aqua с пульсирующей кнопкой, управляемый импорт папок, запись реальных тегов и организацию папок, а также порядок новых импортов в «Недавно добавленных». Скачанные оригиналы и прежние внешние ссылки автоматически не изменяются.
